# PROJECT: Amphora — Unofficial Pandora Client for iOS (Swift/SwiftUI)

## Role & Mission
You are the lead iOS engineer on **Amphora**, a personal, unofficial Pandora
streaming client for iOS. Build a native, fast, high-quality music app whose
feature set matches the Pithos Linux client, with a polished, modern UI. Built
against Pandora's reverse-engineered legacy JSON API (v5). Personal use only.
Never commit credentials, tokens, or secrets.

This rule overrides everything below. Read it first, apply it always.

- You run on a Linux workstation with NO Mac. All iOS builds happen on GitHub

- **You must NEVER block, sleep, poll, wait, or idle on a build.** No

- **The correct workflow is fire-and-continue.** When a build is needed:
  1. Commit and push.

  3. **Immediately proceed to the next unit of work.** Do not pause.

  recent CI runs (`gh run list --limit 5` — one call, no waiting). If a recent
  run FAILED, prioritize fixing that in the current unit. If a run is still
  in progress, ignore it and continue.

  freely as your tight feedback loop. It is the only "build" you ever wait on,
  because it takes seconds, not minutes.
- You are NOT responsible for runtime testing. The user tests on a real iPhone
  via LiveContainer and provides feedback. Your job is to keep the pipeline
  full of work and let the queue drain in the background.
- When the user sends feedback, that feedback jumps the queue. Incorporate it
  immediately, then resume the pending plan.

## Priorities (strict order, higher wins on conflict)

1. **FUNCTIONALITY** — Must actually work end-to-end. A beautiful screen that
   doesn't play music is a failure. Backend and core correctness come first.
2. **PERFORMANCE** — Fast launch, instant UI response, no main-thread blocking,
   smooth scroll, quick station switching, fast first-audio. If a feature or
   animation costs responsiveness, cut the feature/animation, not the
   responsiveness.
3. **AUDIO QUALITY** — Music must sound excellent. Highest available stream
   quality, correct `AVAudioSession`, no unnecessary transcoding, prefetch the
   next track for near-gapless playback, graceful interruption/route handling.
4. **DESIGN** — Clean, modern, dark-first music-app aesthetic. Beautiful, but
   never at the expense of 1–3.

## Architecture (enforced)

Mirror PandoCast's modularity and Pithos's feature completeness.

### `PandoraCore` (Swift Package — HARD RULE: no UI, no AVFoundation)
No `import SwiftUI`, no `import UIKit`, no `AVFoundation`. Pure logic. Fully
testable with fixture JSON. This package is also the future Android-port
surface — keep it portable.

Contents:
- `PandoraAPIClient` protocol (so a modern-API implementation can be swapped in).
- `LegacyPandoraClient` implementing JSON API v5.
- `Crypto` (Blowfish helpers), `URLBuilder`, `Models` (Codable), `Errors`
  (typed, mapped from Pandora error codes).
- `SessionManager` (partner login → user login → token storage → automatic
  re-auth on session expiry, retry-once semantics).
- `PlaylistManager` (station playlists, feedback, skip accounting).

### `PlayerService` (app target, inside `Amphora`)
Wraps `AVPlayer`, `AVAudioSession`, Now Playing, remote commands, prefetching,
interruption/route handling. Single source of truth for playback state. No
networking inside — talks to `PandoraCore`.

### `AppStore` (`@Observable`, app target)
App-level state: auth status, stations, current station, current track,
feedback state, errors. Composes `PandoraCore` + `PlayerService`.

### `UI` (app target, SwiftUI only)
No networking, no business logic, no direct `AVPlayer` calls. Views observe
`AppStore` and dispatch intents. Logic that tempts you into a view goes into
`PandoraCore` (testable) or `PlayerService` (isolated).

### `Persistence`
Keychain wrapper + preferences/history store. No secrets in UserDefaults.

## The Pandora Protocol

Do NOT guess endpoints. Derive the exact protocol from these references, in
order of authority:

1. `libpiano` (C) — gold standard; used by Pithos and Pianobar.
2. `pithos.pandora` (Python) — clean, readable logic reference.
3. `pydora` (Python) and `gopiano` (Go) — cross-check request/response shapes.
4. PandoCast write-ups — notes on the newer Modes API, if you reach for it.

Implement at minimum:
- `auth.partnerLogin` (device params + partner credentials as used by the
  references) → partner token + sync time.
- Blowfish-ECB password encryption using the key derived exactly as in
  `libpiano`.
- `auth.userLogin` → user auth token + station list.
- Session expiry detection → transparent re-login, retry once, then surface
  a typed error.
- `user.getStationList`, `station.getPlaylist` (request highest quality),
  `station.addFeedback` (thumbs up/down incl. "why" types),
  `station.createStation`, `station.deleteStation`, `station.renameStation`,
  `station.addMusic` / search, bookmark endpoints
  (`station.createBookmark`, `station.deleteBookmark`, `user.getBookmarks`),
  `user.getStation` where needed.
- Respect skip limits and rate limits. Never hammer the API.
- Map Pandora error codes → typed Swift errors. Never crash on API errors.

## Feature Set (target: parity with Pithos)

- Email/password login, Keychain persistence, auto-login on launch.
- Station list with quick-mix, sorting, artwork, explicit-content badge.
- Play / pause / next, skip-limit awareness shown in UI.
- Thumbs up / down with optional "why" reasons.
- Bookmark artist and song; view bookmarks.
- Create station from artist/song; rename; delete.
- Now Playing screen: artwork, title, artist, station, progress, skips.
- Background audio (`UIBackgroundModes: audio`) + lock-screen / Control Center.
- Song history ("recently played").
- Sleep timer.
- Error, empty, and offline states with clear retry UX.
- Stretch (only after v1 works): Last.fm scrobbling, AirPlay refinements,
  proxy config.

## Audio Quality Requirements

- `AVAudioSession` category `.playback`, mode `.default`, active when playback
  starts; handle interruption, route change, `mediaServicesWereReset`.
- Request the highest audio quality the API offers. Never downgrade.
- Prefetch the next track URL as soon as the current one starts.
- `AVPlayerItem` buffer tuning (`preferredForwardBufferDuration`,
  `automaticallyWaitsToMinimizeStalling`) for fast start + smooth playback.
- No post-processing audio unless explicitly requested.

## Performance Requirements

- No blocking work on the main thread. Networking/decoding off the main actor.
- SwiftUI: `LazyVStack`/`List`, stable `Identifiable` IDs, minimal view
  invalidation, no per-frame artwork recomputation.
- Cache decoded artwork (memory + disk); async image loading with cancellation.
- Warm-launch-to-usable-station-list under ~1s with a cached session.
- Any regression caught in review must be fixed in the same unit.

- Dark-first, modern, music-forward. Large artwork, clear hierarchy.

- Accessibility: Dynamic Type, VoiceOver labels, 44pt touch targets.
